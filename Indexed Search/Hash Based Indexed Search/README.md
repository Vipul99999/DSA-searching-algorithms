# Hash-Based Indexed Search

Hash-Based Indexed Search is a searching approach that achieves fast data retrieval by transforming a search key into a direct storage location using a **hash function**.

Instead of scanning data sequentially or traversing ordered structures, hash-based searching computes an index position and accesses data directly, making lookup operations extremely efficient.

This technique forms the foundation of modern **databases, caches, key-value stores, indexing systems, distributed storage, and high-performance retrieval engines**.

# Introduction

Searching large datasets efficiently is a fundamental challenge in computer science.

Traditional methods such as linear or block-based searching reduce comparisons but still require partial traversal.

Hash-Based Indexed Search takes a different approach:

```text
Search Key
     ↓
Hash Function
     ↓
Index Location
     ↓
Retrieve Data
```

The goal is to approach **constant-time retrieval** whenever possible.

---

# Motivation

Sequential searching becomes inefficient as datasets grow.

Example:

```text
Find User ID = 100024
```

Traditional search:

```text
Record 1
Record 2
Record 3
...
Record N
```

Hash-based search:

```text
Hash(100024)
↓
Storage Location
↓
Return Result
```

This significantly reduces lookup time.

---

# What is Hash-Based Indexed Search?

Hash-Based Indexed Search stores records in positions generated by a **hash function**.

A hash function converts:

```text
Key → Numeric Index
```

Example:

```text
Hash(52) = 12
```

Data:

```text
Index     Value
12        Record(52)
```

Searching:

```text
Search 52
↓
Compute Hash
↓
Access Position 12
↓
Return Record
```

# Core Components

## 1. Key

Unique identifier used for lookup.

Examples:

* User ID
* Email
* Product Code
* File Identifier

---

## 2. Hash Function

Maps keys into storage locations.

Properties of a good hash function:

* Fast computation
* Uniform distribution
* Minimal collisions
* Deterministic output

Example:

```text
index = key % table_size
```

---

## 3. Hash Table

Primary storage structure.

Example:

```text
Index     Data
0         —
1         A
2         —
3         C
4         B
```

---

## 4. Collision Resolution

Handles situations where multiple keys map to the same location.

---

# Search Workflow

```text
Input Key
    ↓
Generate Hash
    ↓
Locate Bucket
    ↓
Resolve Collision (if needed)
    ↓
Return Data
```

---

# Collision Handling

Since different keys may produce the same index:

```text
Hash(A) = 7
Hash(B) = 7
```

Collision management becomes necessary.

Common approaches:

### Separate Chaining

```text
7 → A → B → C
```

Store multiple elements in linked structures.

---

### Open Addressing

Search for the next available location.

Methods:

* Linear Probing
* Quadratic Probing
* Double Hashing

# Algorithms Included

## 1. Hash Table Search

Direct indexing using hash computation.

Characteristics:

* Fast average retrieval
* Simple implementation
* Widely used

Typical Complexity:

```text
Average: O(1)
Worst: O(n)
```

---

## 2. Extendible Hashing

Dynamic hashing that grows gradually.

Characteristics:

* Supports scalable indexing
* Efficient insertions
* Reduces rehashing

Typical Complexity:

```text
Average: O(1)
```

---

## 3. Linear Hashing

Incrementally expands storage.

Characteristics:

* Dynamic bucket allocation
* Avoids global rebuild

Typical Complexity:

```text
Average: O(1)
```

---

## 4. Dynamic Hashing

Adjusts index structure automatically.

Characteristics:

* Flexible growth
* Efficient updates

Typical Complexity:

```text
Average: O(1)
```

---

## 5. Cuckoo Hashing

Uses multiple hash functions.

Characteristics:

* Constant lookup time
* Relocation-based insertion

Typical Complexity:

```text
Lookup: O(1)
```

---

## 6. Perfect Hashing

Collision-free mapping for fixed datasets.

Characteristics:

* Deterministic lookup
* Ideal for static collections

Typical Complexity:

```text
Lookup: O(1)
```

# Advantages

* Extremely fast lookups
* Near constant-time access
* Efficient for large datasets
* Scalable indexing
* Suitable for real-time systems
* Simple search implementation

---

# Limitations

* Collision overhead
* Additional memory consumption
* Performance depends on hash quality
* Dynamic resizing cost
* Poor locality for range queries

# Conclusion

Hash-Based Indexed Search improves retrieval performance by replacing traversal with direct index computation.

By mapping keys to storage locations through hashing, these algorithms achieve extremely fast access times and serve as the backbone of modern databases, caching systems, and large-scale distributed applications.

When rapid lookup is the primary requirement, hash-based indexing is one of the most effective search strategies available.
